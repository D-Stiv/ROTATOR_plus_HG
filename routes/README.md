# Synthetic Intermodal Route Dataset

Synthetic Intermodal Route Dataset for ROTATOR+HG

The code in this repository generates the dataset used in our approach: <br>
Steve Gounoue, Genivika Mann, Rajjat Dadwal, and Elena Demidova. “ROTATOR+HG: Representation Learning for Intermodal Routes with Hypergraph”. In: Proceedings of the 34th ACM International Conference on Advances in Geographic Information Systems (SIGSPATIAL '26), 2026. DOI: https://doi.org/10.1145/3841645.3843039. <br>
If you use the source code or generated dataset, please cite our research. <br>

<b>Notes:</b> <br>
1) The code generates synthetic intermodal routes for the **Wangerland region, Germany**, using an intermodal transportation graph and sequences of Points of Interest (POIs). <br>
2) The POI sequences originate from the **DIRECT** approach by Mann et al. [1], while the underlying geographic and transportation network is based on **OpenStreetMap (OSM)** [2]. <br>
3) The `resources/` directory must be prepared before executing the route-generation pipeline and must contain the graph, POI sequences, and POI-to-graph mapping described below. <br>

<b>Introduction:</b> The provided software generates synthetic intermodal routes representing touristic day trips in the Wangerland region of Germany. Routes connect sequences of 2 to 7 POIs, such as restaurants, parks, museums, and hotels, using combinations of available transportation modes. <br>

<b>Implementation Overview:</b> The project follows a route-generation pipeline that maps POI sequences generated using DIRECT [1] onto an intermodal transportation graph derived from OpenStreetMap [2]. Each POI is associated with its closest graph node, after which routes connecting consecutive POIs are generated under configurable constraints on travel time, distance, transfers, transport-mode sequences, mode proportions, speed, and route diversity. The resulting routes have an average duration of approximately 1.5 to 2 hours, with a maximum duration of around 4.5 hours, and travel distances ranging from a few meters to several kilometers. The generated dataset is split into training, validation, and test sets using a ratio of **0.7 / 0.1 / 0.2**, respectively. <br>

<b>Project Directory Structure:</b> The route-generation project contains the main execution script, route construction utilities, and a `resources/` directory containing the external data required to generate the routes. <br>

```text
Route/
│
├── resources/
│   ├── graph.pkl
│   ├── mapping_poi_graph.csv
│   └── poi_seq.csv
│
├── main.py
├── README.md
└── route_utils.py
```

<b>Folder and File Descriptions:</b> <br>

<b>resources/</b> <br>
Contains the external data required by the route-generation pipeline. The folder must be prepared before executing `main.py`. <br>

<b>resources/graph.pkl</b> <br>
Contains the intermodal transportation network describing the Wangerland region. <br>

Each node is associated with: <br>
+ Node ID <br>
+ Available transport mode <br>
+ Geographic latitude and longitude coordinates <br>

Each edge is associated with: <br>
+ Transport mode <br>
+ Distance <br>
+ Average travel time <br>

<b>resources/poi_seq.csv</b> <br>
Contains the POI sequences from which the intermodal routes are generated. POIs are represented using their **POI IDs**. The complete list of POI sequences is provided by Mann et al. [1]. <br>

<b>resources/mapping_poi_graph.csv</b> <br>
Contains the mapping between each **POI ID** and its **closest node ID** in the intermodal transportation graph. This mapping allows the POI sequences to be projected onto the graph before route generation. <br>

<b>route_utils.py</b> <br>
Contains utility functions used for route construction and route generation. <br>

<b>main.py</b> <br>
Main entry point for generating the synthetic intermodal routes. The route-generation parameters and constraints are exposed as command-line arguments. <br>

<b>Route Generation:</b> <br>
Once the required files have been placed in `resources/`, the synthetic intermodal routes can be generated by executing `main.py`. The following command corresponds to the configuration used for the released dataset: <br>

```bash
python3 main.py --mode_coefficients "{}" --global_transfers 10 --max_time 21600 --unauthorized_mode_sequences "['bike', 'drive']" "['bus', 'drive']" "['drive', 'bike']" "['drive', 'bus']" "['bike', 'walk', 'drive']" "['bus', 'walk', 'drive']" "['drive', 'walk', 'bike']" "['drive', 'walk', 'bus']" --penalty 1.5 --max_transfers 3 --list_weights "['distance', 'time']" --min_dist_mode 50 --m_prop_tolerance 0.15 1.0 --modes_prop "[{}, {'bus': 0.1, 'bike': 0.2, 'walk': 0.7}, {'bus': 0.2, 'bike': 0.2, 'walk': 0.6}, {'bus': 0.8, 'bike': 0, 'walk': 0.2}, {'bus': 0.15, 'bike': 0.6, 'walk': 0.25}, {'bus': 0.4, 'bike': 0.4, 'walk': 0.2}, {'bus': 0.2, 'bike': 0, 'walk': 0.8}, {'bus': 0, 'bike': 0.8, 'walk': 0.2}]"
```

<b>Route Constraints:</b> <br>

| Parameter | Description |
|---|---|
| `--max_distance` | Maximum total distance of a generated route, in meters. If `None`, no maximum distance constraint is applied. |
| `--max_time` | Maximum total duration of a generated route, in seconds. In the provided configuration, `21600` seconds corresponds to 6 hours. |
| `--max_transfers` | Maximum number of transfers allowed for consecutive pairwise POIs. |
| `--global_transfers` | Maximum number of transfers allowed within an individual route. |
| `--authorized_mode_sequences` | Restricts routes to explicitly authorized transport-mode sequences, e.g., `['walk', 'bus', 'walk']`. Multiple sequences can be provided. |
| `--unauthorized_mode_sequences` | Explicitly prohibits specified transport-mode sequences, e.g., `['drive', 'walk']`. Multiple sequences can be provided. |
| `--penalty` | Penalty used to promote diversity among generated routes. A larger value places a stronger penalty on insufficient route diversity. The provided configuration uses `1.5`. |

<b>Transport-Mode Coefficients:</b> <br>

`--mode_coefficients` specifies coefficients associated with transport modes and transfers. These coefficients are used to weight graph edges when constructing routes through the shortest-path algorithm. <br>

The default configuration is:

```text
[{'transfer': 2, 'walk': 1, 'bike': 0.5, 'drive': 0.1, 'bus': 0.1, 'train': 0.1, 'tram': 0.1}]
```

In the provided route-generation command, `{}` is supplied, meaning that no explicit coefficients are specified through the command line. <br>

<b>Speed Constraints:</b> <br>
The following parameters can be used to filter implausible route segments based on their implied travel speeds. <br>

| Parameter | Description |
|---|---|
| `--distance_thresh_minspeed_m` | Distance threshold, in meters, above which the minimum-speed filter is applied. For example, `1000` corresponds to 1 km. |
| `--time_thresh_maxspeed_s` | Time threshold, in seconds, used for applying the maximum-speed filter. For example, `1800` corresponds to 30 minutes. |
| `--min_speed_mps` | Minimum allowed speed in meters per second. For example, `0.5` m/s corresponds to 1.8 km/h. If omitted, the implementation uses twice the walking speed. |
| `--max_speed_mps` | Maximum allowed speed in meters per second. For example, `10` m/s corresponds to 36 km/h. If omitted, the implementation uses half the tram speed. |

<b>Diversity and Route Overlap:</b> <br>

| Parameter | Description |
|---|---|
| `--overlap_threshold` | Threshold controlling the permitted overlap between route hexagons. A value of `1` allows full overlap, whereas `0` does not allow overlap. |
| `--list_weights` | List of edge attributes used as weights when evaluating routes. In the provided configuration, the attributes are `distance` and `time`. |

The released configuration uses:

```text
['distance', 'time']
```

<b>Mode-Distance Constraints:</b> <br>

| Parameter | Description |
|---|---|
| `--min_dist_mode` | Minimum distance, in meters, required for consecutive edges using the same transport mode. If `None`, no minimum-distance constraint is applied. The provided configuration uses `50` meters. |
| `--modes_prop` | Specifies target proportions of travel modes, based on their distance ratios, for routes with a given number of modes. If `None`, all modes are considered without enforcing specific proportions. |
| `--m_prop_tolerance` | Tolerance allowed around the target mode proportions. For example, `0.15` permits deviations of up to 0.15 from the specified proportions. |

The provided configuration uses the following target mode proportions:

```text
[
    {},
    {'bus': 0.1, 'bike': 0.2, 'walk': 0.7},
    {'bus': 0.2, 'bike': 0.2, 'walk': 0.6},
    {'bus': 0.8, 'bike': 0, 'walk': 0.2},
    {'bus': 0.15, 'bike': 0.6, 'walk': 0.25},
    {'bus': 0.4, 'bike': 0.4, 'walk': 0.2},
    {'bus': 0.2, 'bike': 0, 'walk': 0.8},
    {'bus': 0, 'bike': 0.8, 'walk': 0.2}
]
```

The entries correspond to routes with different numbers of transport modes. The first entry, `{}`, imposes no specific mode-proportion constraint. <br>

<b>Configuration Used for the Released Dataset:</b> <br>
The released synthetic intermodal route dataset was generated using the following main configuration: <br>

+ Maximum route duration: `21600` seconds (6 hours) <br>
+ Maximum transfers per consecutive POIs: `3` <br>
+ Global transfer limit: `10` <br>
+ Diversity penalty: `1.5` <br>
+ Minimum distance for consecutive edges with the same mode: `50` meters <br>
+ Mode-proportion tolerance: `0.15`, `1.0` (take all) <br>
+ Transfer segments included in mode-proportion calculations <br>
+ Route weights: `distance` and `time` <br>

The following transport-mode sequences are explicitly unauthorized: <br>
+ `bike → drive` <br>
+ `bus → drive` <br>
+ `drive → bike` <br>
+ `drive → bus` <br>
+ `bike → walk → drive` <br>
+ `bus → walk → drive` <br>
+ `drive → walk → bike` <br>
+ `drive → walk → bus` <br>

The mode-coefficient configuration is:

```text
{}
```

The mode-proportion configurations are:

```text
{}
{'bus': 0.1, 'bike': 0.2, 'walk': 0.7}
{'bus': 0.2, 'bike': 0.2, 'walk': 0.6}
{'bus': 0.8, 'bike': 0, 'walk': 0.2}
{'bus': 0.15, 'bike': 0.6, 'walk': 0.25}
{'bus': 0.4, 'bike': 0.4, 'walk': 0.2}
{'bus': 0.2, 'bike': 0, 'walk': 0.8}
{'bus': 0, 'bike': 0.8, 'walk': 0.2}
```
